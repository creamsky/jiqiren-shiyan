# SCOUT MINI 桩桶迷宫实验

在真机控制台的实验库选择 **迷宫探索**。地图、出口和路线由控制台主机维护，同网段观看者可以看到同一轮地图。[打开真机控制台](http://127.0.0.1:8765/hardware/)

## 一轮怎么跑

1. 连接真机并取得控制权。确认底盘处于 CAN 控制档，车已停稳，点击 **准备迷宫**。准备阶段车辆保持停稳。控制台从当前位置创建本轮地图，在雷达、定位和规划已在线时沿用当前传感器。
2. 点 **开始探索**，车辆才开始运动。默认 **地图探索**，会根据已建立的通行图搜索可到达的未知区域。想让车沿眼前通道持续行驶，可以在 **探索方式与搜索区** 选择 **自主漫游**。
3. 雷达扫到出口后，点 **在图上选出口**，再点通行图上出口内侧、已观测且有车身净距的空地。运行中也可以点 **更改出口**。车到出口区并确认停稳后，本轮完成。未指定出口时，车会继续探索开阔区。
4. 临时观察场地时点 **暂停**，本轮地图和出口会保留。点 **继续** 会先复核通路。点 **停止运动** 结束本轮，需要下一轮时再点 **准备迷宫**。

大致知道出口方向时，可以展开 **探索方式与搜索区**，填写相对本轮起点向前、向左的距离，单位为米。向后、向右填负数。点 **标记搜索区** 后，车会优先朝该方向找路。实际结束位置仍需在图上选出口。

## 看图和处理中断

| 界面或提示 | 如何使用 |
| --- | --- |
| **累计点云** | 进入迷宫时默认打开三维地图。地板点默认隐藏，可切换同一张图的二维俯视。拖动旋转、滚轮缩放。 |
| **通行图** | 查看已观测区域、障碍和估计底座，选取出口。青线表示实走轨迹，黄线表示规划路线。 |
| **实时点云** | 查看最近一帧雷达回波，便于核对当前是否仍在出点。累计点云与通行图在浏览器每秒更新一次。 |
| 数据暂时中断 | 车先停车。仍有控制权、本轮定位原点未变、底盘已确认停稳，并且数据连续正常约 0.7 秒后，运行中的任务会重新选路。手动暂停的任务会保持暂停。 |
| 提示任务已中止 | 数据超过 12 秒仍未恢复时，本轮结束。遇到底盘故障、控制连接断开或定位地图变化时，先按提示检查，再重新连接或准备迷宫。新地图上的出口需要重新选点。 |

## 两种选路方法

| 策略 | 开阔通道 | 遇到阻挡 |
| --- | --- | --- |
| 地图探索 | 在累计栅格的可达区域寻找已知与未知的交界，结合搜索方向、通路距离和到访次数选目标。 | 在多条候选路径中复核起步转向和车身扫过的位置。无进展时为失败区域设置 30 秒重试间隔，尝试其他岔路和补充观测的位置。 |
| 自主漫游 | 在当前朝向两侧检查 16 个方向、最长 1.7 m 的已观测通道，优先延续朝向、净距大且到访少的路线。直道满足条件时，在到达旧目标前续接新前视点。 | 缩短前视距离，检查侧向和掉头方向。近处均无法通行时，在累计地图中查找可退回的岔口。指定出口后优先沿地图向出口导航。 |

两者使用同一车端路径跟踪和 CAN 控制。每个运动目标距车最多 2 m，远处的已知出口分段到达。更新前视点必须匹配当前任务标识和 SLAM 地图版本。车端限制线速度指令幅值为 0.18 m/s，角速度幅值为 0.38 rad/s。目标点受阻时，先检查同一曲率下较低的速度。实测速度的制动范围也受阻时，发零速，停稳后再选路。雷达、定位或规划器短暂断流时立即停车。同一轮数据恢复并连续稳定 0.7 秒，而且底盘确认停稳后，才重新选路。超过 12 秒仍未恢复则结束本轮。控制权交接、CAN 反馈失效和地图代际变化会终止当前运动授权。

探索部分参考了 ROS Noetic 的前沿搜索，车上复用已部署的 Navfn 路径服务与 SCOUT 的 CAN 链路。这里在每段起步、转向和制动时额外检查矩形车身与估计的桩桶底座。[explore_lite 前沿搜索源码](https://github.com/hrnr/m-explore/blob/noetic-devel/explore/src/frontier_search.cpp) · [ROS Navfn](https://index.ros.org/p/navfn/) · [AgileX SCOUT ROS](https://github.com/agilexrobotics/scout_ros)

## 地图与现场校准

**三维累计点云。** 使用车上 SLAM 输出的 `/cloud_registered`，在 `camera_init` 坐标系中按水平 10 cm、竖直 4 cm 体素采样。车端逐帧轮换取样位置，降低细桩连续落在采样间隙的概率。一个体素至少在三个不同扫描时刻出现、跨度达到 0.3 秒才进入累计显示。车辆重新看向原处时，至少八帧真实射线经过原点的三维位置、打到更远处，且最后一次命中已过 1.4 秒，才能清掉该点。大图超过 65,536 个有效显示体素时加粗水平分辨率，保留竖向分辨率。网页首次获取快照，此后每秒获取一次增量。

**看清地面附近的路障。** 默认开启「障碍增强」、隐藏有局部地面支持的地板点。算法按 1 m 分区拟合平面，用参与拟合的点分布、坡度、残差及相邻分区的连续性限制地面范围。距已确认地面 4 cm 以内的回波归入地面，向上 4–90 cm 的回波着暖色、加大点径。悬空高处回波降低亮度。缺少水平覆盖、地面模型不可靠的地方保留回波。迷宫实验还会叠加最近一帧经车端筛选的实测近障，过期自动撤下。图例的「近地凸起」表示实测高度，可能是桩桶、台阶、墙脚或其他物体。显示设置中可打开「显示已确认地面」做对照，采样点和二维通行判断都保留。分区估计的参考实现见 [Patchwork++](https://github.com/url-kaist/patchwork-plusplus)。

**车身与盲区。** 本车固定外参实读为 `[0, 0, 0.28] m`，旋转为单位矩阵。28 cm 是雷达相对 SLAM 机体坐标原点的高度偏移。累计建图读取实机外参和点云时刻的完整位姿，剔除实际车身投影内、雷达以下的自身回波，两侧紧贴车身的回波仍保留。近车低处看不到的物体只能依赖先前观测；从来没有被雷达照到的矮障碍可能在图中缺失。观察不到桶底的实际宽度由下述双桶校准处理。

**二维通行图。** 栅格边长 10 cm。控制台用观测时刻的 `camera_init ← body` 位姿累计车端运动补偿后的全向回波。新回波立即参与避障，途经的人也会先被避让。清除占用时要同时看到穿过原栅格的平面射线，以及穿过原来各个观测高度、终点更远的三维射线。短时障碍至少需六帧清除证据和 1.2 秒。持续障碍（至少四帧命中、跨度达到 1.2 秒）至少需十二帧和 2.4 秒。雷达从桶顶上方扫过或暂时被挡住时会保留旧障碍。网页刷新频率独立于车端制动和后端建图。

这套判别依靠观测几何。侧向遮挡、缺少同高度回波时，清除会推迟；返回次数只表示当前证据强度。车身投影按平整场地计算，大场地的 SLAM 漂移会影响远处选点。点云中看到的桶身、通行图中的估计底座和实际底座宽度应在现场对照。

底座单侧额外伸出量暂设 **18 cm**，作用于每侧观测障碍。课程给出的底盘尺寸是 **65 × 55 cm**，程序另留纵向每端 1 cm、横向每侧 1.5 cm 的车体余量。现场轮胎、支架、雷达安装偏移和桩桶的实际尺寸都可能改变最窄可通过的间隙。

**双桶静态校准。** 车停稳，量两只桶底座内缘的真实最小净宽，再量相同横截面两个桶在雷达扫描高度的内缘净宽。在对称摆放、两桶同规格时，两种净宽之差除以二，是单侧外扩量。对方底座再测角朝通道的摆法，选较大值并计入测量误差。两桶不同规格或布置不对称时，分别测各自从可见表面到最外角的距离，取较大值。实测车体最大宽度应包括突出轮胎和附件。把确认过的外扩量以米填入 `calibration.json`，重启控制台后生效。起步时若显示近距回波，应先核对回波来源和实物间隙，再做贴边通行实验。

## 代码入口

- `scan_stream.py`、`scan-stream.cjs` 读取同步 ROS 观测。车端话题为 `/lab26/maze_obstacles` 和 `/lab26/clearing_rays`。
- `registered-map.cjs` 累计世界坐标中的三维点云，向网页提供快照、增量点和已移除点的索引。
- `maze-map.cjs` 维护分块栅格、净距、轨迹和全图搜索。`roam.cjs` 选择局部漫游方向。`mission.cjs` 管理停车确认、运动授权、续接和重选。
- `view.js`、`view.css` 提供真机控制台内的地图和目标交互。车端制动和前视续接实现位于 `实验三扩展/实验二/lab26/catkin_ws/src/basic_control/`。
- 在项目根目录用 PowerShell 7 执行 `node --test '迷宫/*.test.cjs' '控制台/*.test.cjs'`。回归使用固定观测与本机测试端口，不会连接或驱动车辆。
