# 机器人控制台

## 打开仿真或真机

双击根目录的 **启动控制台.cmd**。网页默认进入“本地仿真”，点 **启动仿真** 后连接专用 Ubuntu 虚拟机。在“原生 Gazebo”看车体和场地，在“点云选点”布置桩桶或更改目标。[打开本地仿真页面](http://127.0.0.1:8765/simulation/)

在同一页选择 **真实机器人**，再点 **连接真机**。获得控制权并准备实验后，可以在真实点云中选择 XY 目标。两种模式使用不同的 SSH 配置，真机选点应在当前 SLAM 坐标系下完成。结束整套项目可双击 **关闭控制台.cmd**。

- 无需账号。同一局域网内按连接来源 IP 识别设备，同一电脑多个页面、多个浏览器合并显示一次；本机回环地址与本机网卡地址也合并。可点击顶部名称改名。它不是硬件序列号，换网络/IP 后可能获得新编号；经过代理/NAT 的设备可能合并，适用于同一 Wi-Fi / 热点直连场景。来源 IP 使用实际 TCP 连接地址，不相信客户端填写的身份或转发头。名称本身不授予管理员权限。
- 每个页面持有独立控制会话，设备编号不共享驾驶权限。一次只有一个页面控制，其他人可观看、排队、停车。结束控制、页面失联后，必须收到连续静止反馈才交接；队首需在 30 秒内主动确认。管理员接管同样先停车再交接，不自动开动。
- 点云默认显示机器人端将最近一秒的 `/cloud_registered` 完整各帧聚合后的结果。各帧已经由 FAST-LIO 转到同一世界坐标系；每秒通过一条共享 SSH 连接传回电脑，再提供给所有网页。窗口每秒替换，坐标系或时间戳回退时清空，避免混合不同地图。它不是无限累积地图，动态物体可能留下约一秒的轨迹。
- “显示设置 → 原始单帧”显示 `/velodyne_points` 最新一帧全部有限 XYZ 点，每秒刷新。无 8000 点截断；无效 NaN/Inf 点剔除。原始帧没有世界坐标变换，因此不叠加定位轨迹。前端缓冲按实际点数增长，仅保留异常数据的内存保护。
- FAST-LIO 的 `point_filter_num=4`、`dense_publish_en=false` 及运动控制程序保持原配置。`point_filter_num` 和稠密发布开关均为 [FAST-LIO 原有功能](https://github.com/hku-mars/FAST_LIO/blob/main/src/laserMapping.cpp)。独立只读程序为 `robot-cloud-stream.cpp`，部署于 `/home/nvidia/robot-lab-viewer/cloud-stream`，由本机服务启动和维护，不订阅或发布运动指令。

## 连接与操作

1. 点击 ping，查看机器人网络是否可达。ping 成功只表示 ICMP 有回应，不代表 SSH 登录或控制接口连接成功。
2. 启动器自动将本机 `18766` 端口转发到机器人回环地址 `127.0.0.1:8766`。机器人必须已部署支持控制台的新版本；界面显示控制器连接成功后再取得控制权。启动日志在 `控制台/logs/`。
3. 在实验列表选择任务，取得控制权后开始任务，并查看状态和运行日志。实验一仅支持开始与停止，不提供中途续跑；实验二支持暂停与继续。停止会终止本轮任务，再次开始是一轮新任务。由实验一切换回实验二时先准备传感器与控制程序，就绪后需再次点击开始，不在准备完成时自动运动。
4. 手动驾驶是共享功能，不随实验选择重复实现。切换到手动模式后，按住 W 前进、S 后退、A 左转、D 右转；也可按住页面上的方向按钮。松开停车，空格执行停止。
5. 手动与自动不会同时发送运动命令。操作页面失去焦点、失联或控制心跳停止时停车；重新取得控制权后再操作。

键盘驾驶也可直接点击“启用键盘驾驶”，自动取得本窗口控制权并等待机器人确认。下拉框焦点不拦截 WASD，编辑输入框时不接管打字。若机器人拒绝手动模式，驾驶面板显示具体原因。部署和修复证据见 [WASD 修复与部署核对](WASD修复与部署核对.md)，机器人源码仓见 [仓库说明](机器人端源码仓说明.md)。

本机服务在启动窗口运行。保持该窗口开启；结束使用时双击根目录 `关闭控制台.cmd`，该入口发送停车并关闭本项目的前端服务，保留 SSH 连接。

进度条：实验一按实际流程事件显示阶段进度，建图采集段按 30 秒计时；实验二按直线进度，八字按总长 `4πR` 的路线进度。暂停保留进度，重新启动新任务会从零开始。八字可选当前位置作为交叉点或圆外侧；先准备，再显式点击启动。

## SSH 隧道故障排查

正常操作不需要手工建立隧道。仅在排查启动器连接问题、且启动器已关闭时，可在 PowerShell 7 终端手工执行以下命令，并保持终端开启：

```powershell
& "$env:WINDIR\System32\OpenSSH\ssh.exe" -i "$env:USERPROFILE\.ssh\robot_lab_ed25519" -o BatchMode=yes -o StrictHostKeyChecking=yes -o ExitOnForwardFailure=yes -o ServerAliveInterval=5 -o ServerAliveCountMax=3 -L 127.0.0.1:18766:127.0.0.1:8766 nvidia@10.226.235.72 "bash /home/nvidia/lab26/start_console.sh"
```

专用私钥已于 2026-11-07 恢复，并验证批处理 SSH 登录成功；脚本与笔记不保存账户密码。控制台启动器要求该私钥及已核验的主机密钥；缺失时查看错误日志并恢复配置，不会静默忽略主机密钥检查。上述命令会运行实车控制台入口，但不会部署新文件。

## 控制设置

- 以下运动设置针对实验二及共享手动驾驶；实验一是现有建图与定位验证流程，不发送实验二的 45°/5 m 自动运动。
- 实验二自动任务为先转向 45°，再直行 5 m。自动直行速度上限 0.50 m/s，手动 W/S 上限 1.50 m/s，转向上限 0.30 rad/s。
- 障碍距离以雷达为中心，检查当前运动方向。1 m 内暂停，退出到 1.2 m 外并稳定 2 秒后自动续跑；原目标和进度保留。
- 障碍来自雷达点云，不识别人。检测保留半径小于 0.45 m 的自身过滤，排除高度绝对值超过 0.35 m 的点，至少 3 个有效点才触发；1 m 是所选运动区域内有效点的阈值，不代表整个 1 m 球体内的任何障碍都一定能检测。
- 定位、雷达、底盘反馈等故障仍停车，不归入可自动恢复的普通障碍暂停。
- 航向 PD：Kp=0.8、Kd=0.08，微分项使用滤波实测航向角速度；自动线加速度 0.20 m/s²，手动线加速度 0.60 m/s²（起步快三倍），角加速度 0.60 rad/s²。保护停车、松键停车立即归零。
- 参数和代码验证记录见各实验说明。完整实车运动验收由用户现场操作完成，仿真不作为已实测结论。

## 三维点云

主画面显示真实 XYZ 点云的三维投影，拖动旋转、滚轮缩放，可切换俯视或复位，颜色表示高度。可选择 5、15 或 30 m 范围。界面约每秒更新一次，最多显示 1000 个采样点；这是实时雷达视图，不是 RViz 屏幕镜像或完整累积地图。安全检测仍使用全部有效输入点。

W/S 只前进、后退，A/D 只原地左旋、右旋，不混合两轴运动。切换方向时取消旧轴输出，新的指令平滑起步。遥控器直接连接底盘，电脑通过 SSH 与车载 CAN 控制，不要求遥控器连接电脑。底盘遥控器接管时，界面显示实际模式，不能绕过硬件优先权。

按用户要求，控制台启动时执行 `keep_screen_awake.sh`：关闭空闲熄屏和 DPMS，不修改 lock-enabled、不执行解锁。旧版布局保存在 `归档/控制台旧版/`。

超过 3 秒未更新时标记为过期并淡化旧点，无数据或连接失败会明确提示。不要将旧画面视为当前通道清空。显示帧来自雷达，属于局部点云，不代表建图全局坐标或实验一地图保存已成功。

## 常见状态

| 状态 | 处理 |
| --- | --- |
| ping 不通 | 检查实车电源、电脑与机器人网络及 IP |
| ping 通，控制器未连接 | 检查 SSH 登录、端口转发和机器人新控制程序 |
| SSH 首次确认主机指纹 | 与机器人核对后接受，再连接 |
| 页面失去控制权 | 确认没有其他页面操作，回到当前页面重新取得控制权 |
| 故障停车 | 查看状态原因，排除定位、传感器或底盘问题后重新开始 |
