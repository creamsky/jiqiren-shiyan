# 实验三扩展的导航方法

当前 XY 目标导航接入 ROS Noetic 的 **Navfn 全局规划器和 DWA 局部规划器**，入口为 `dwa/navigation.launch`，参数为 `dwa/navigation.yaml`。`实验三/src/navigation.cpp` 保留原实验三及旧导航实现，当前启用 `xy_use_dwa` 的 XY 任务通过 `dwa_client.h` 执行。

## 数据到运动的过程

1. 前端点选或 `goto_xy.py` 下发当前 SLAM 坐标系 `camera_init` 中的目标 X、Y，单位米，单次距离最多 30 m。重新准备传感器可能改变定位原点，须重新选点。
2. ROS/C++ 控制器读取定位、底盘反馈和雷达点云，发布 `/lab26/chassis_odom` 与车身外的有效障碍点 `/lab26/obstacles`。
3. `move_base` 将点云写入障碍层并膨胀，Navfn 根据代价地图更新路径。DWA 在当前速度和加速度约束内采样线速度、角速度，预测轨迹，再根据路径、目标和障碍代价选择可行速度。
4. Python 适配程序 `dwa/bridge.py` 转发当前目标的速度提议，C++ 控制器核对目标标识和数据时效，限制加速度，并用原始障碍点检查车身及制动扫掠范围，最后通过 CAN 下发速度。
5. 进入目标 **20 cm** 半径后锁定停车，底盘线速低于 0.02 m/s、角速低于 0.03 rad/s 并稳定 0.30 s 后结束。终点不要求回正朝向。

XY 接续规划器绕开障碍后，从当前位姿重新检查朝向终点的局部走廊。通路持续通过车身检查时，直接沿该方向行进。原实验的指定直线跟踪任务仍会接回指定直线。

## 当前基础参数

| 项目 | 配置 |
| --- | --- |
| 路径更新 / 控制频率 | 2 Hz / 10 Hz |
| 滚动全局地图 | 70 × 70 m，栅格 0.10 m |
| 滚动局部地图 | 8 × 8 m，栅格 0.04 m |
| 车身轮廓 | 0.65 × 0.55 m 矩形，额外轮廓留量 0.015 m |
| 全局 / 局部膨胀半径 | 0.65 m / 0.60 m |
| 线速度 | −0.10 至 0.50 m/s |
| 角速度 | 最大 0.70 rad/s，支持原地转向 |
| 加速度上限 | 线加速度 0.20 m/s²，角加速度 0.60 rad/s² |
| DWA 预测时域 | 2.5 s |
| 速度采样数 | 线速度 15，角速度 25 |
| 路径 / 目标 / 障碍权重 | 16 / 20 / 0.08 |

Gazebo 工程加载同一份基础配置，可用 launch 覆盖的候选参数进行现场对照。仿真使用说明和模型版本见 [仿真说明](仿真/README.md)。

## 倒车、受阻和故障

通路判断同时使用两类点云信息。近处障碍回波参与车身和制动扫掠检查。对于返回点较远的射线，只用从雷达出发且仍在雷达平面上下 10 cm 内的那一段补充车宽覆盖。任意落在运动走廊内的近处障碍仍能否决该动作。向前或向后纯直行时，检查当前实速的制动扫掠和指令方向的净距；反方向保险杠边缘的点不会单独拦住驶离它的直行，转动时仍检查两端。

当当前朝向存在出口时，接管规划器会选取在观测范围和制动条件下能执行的直行段。若没有连续来路可供回溯，还可根据当前扫描检查一小段后移能否腾出可转入的支路。预测位置只用来挑选停车点，实际转向由到达后新扫描决定。

常规 DWA 按实际位姿和倒车反馈累计本轮倒退距离，约 20 cm 后限制负线速度，再前进 15 cm 后重新允许倒车。

同一 XY 目标在 DWA 和本地规划器之间共享连续的位姿序列，按前进和原地转向两种动作记录，由下发指令和底盘反馈共同确认。正常短退会消费对应的轨迹，人工接管、暂停、位姿不连续和新目标会断开轨迹。局部规划器中用于观察出口的转向有固定复查时刻，转动中的连续控制周期不会延后下一次规划。

受阻时优先检查当前位置可转入的侧路。需要退回时按实走顺序逆向跟踪相邻轨迹点，弯道随轨迹转向，原地转弯处先停下平移再逆向旋转。岔口或轨迹起点决定总回退距离。速度限制、后方观测和制动扫掠每周期生效。后方遮挡时停车，通道持续恢复且位姿仍与来路吻合才接续。没有可行分支或连续实走轨迹时等待。

侧路选择按当前位置和世界坐标朝向记忆已试分支，再次到达同一岔口时跳过相近方向。发现候选出口后停车复核旋转范围和通道宽度，转出后从实际位置向原目标规划。若原方向的障碍移开且堵点以远的通道持续有清晰观测，也可恢复原方向。岔口由实时观测识别，尚未构建完整的迷宫拓扑图。

没有可行轨迹时输出零速度并重新规划。定位、点云、控制提议或 CAN 反馈超时，以及底盘/通信故障会停车，前端显示具体原因。`errno 105` 是 CAN 发送队列问题，应结合总线 ACK、接口状态与实机日志诊断。

当前地图将未观测区域按可规划区域处理，因此路线只是有限观测条件下的候选。原始点云过滤仍是范围及高度筛选，尚需在高位雷达模型中验证地面回波、低矮障碍和自遮挡。MPC、MPPI 和电池能量模型尚未接入当前真机控制链路。

## 验证与源码

旧的平面模拟程序、模拟结果和算法排名已从当前工作树删除。它们不能用作 Gazebo 物理仿真或真机避障的验收依据。Gazebo 环境、传感器、车辆运动和算法的动态验收以实际运行记录为准。

`diagnostics/` 保留已有真实控制 CSV、现场状态 JSON 及历史故障分析。历史记录中的算法和参数只对应当时部署，不代表本次 DWA 实现已完成同样验收。

- `goto_xy.py`、`robot.sh`：目标、心跳、日志及机器人命令入口。
- `dwa/navigation.yaml`、`dwa/navigation.launch`：Navfn、DWA 和代价地图配置。
- `dwa/bridge.py`：ROS action 目标与带标识的速度提议。
- `实验二/lab26/catkin_ws/src/basic_control/include/basic_control/dwa_client.h`：目标状态、提议时效、到达和短退限制。
- `实验二/lab26/catkin_ws/src/basic_control/src/basic_control.cpp`：传感器新鲜度、扫掠检查及 CAN 输出。
- `仿真/ros/scout_lab/`：厂家 Gazebo 车辆、顶部雷达、场景和仿真驾驶接口。

机器人命令与部署位置见 [README](README.md)。
